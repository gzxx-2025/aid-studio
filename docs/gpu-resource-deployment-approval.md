# GPU调度器生产部署批准单

## 硬门禁

1. 重新运行222本机只读预检，报告不超过5分钟。
2. `safeToRequestApproval=true`；任何 `UNKNOWN`、活跃任务或GPU高利用率都阻断。
3. 管理员确认本次纳入的服务、将停止/重启的服务和预计中断时间。
4. 管理员确认FastH3遗留会话已经完成、凭据已经轮换，但尚未执行清理。
5. 配置、数据库和systemd unit先备份到带时间戳目录，回滚命令已验证。
6. 首次只部署控制面和观察模式Agent；不收紧SSH、Docker或GPU设备权限。
7. 每个固定执行适配器单独通过空跑、单任务和故障回滚后，才把对应服务标记为 `adapterReady=true`。

## 批准时必须展示

- 预检生成时间、有效期和approval token；
- 三个ComfyUI队列状态；
- 三个Celery队列状态；
- 两张GPU的利用率、显存和计算进程；
- 本次新增/覆盖文件；
- 本次会停止或重启的进程；
- 数据库迁移与回滚方式；
- 预计影响窗口。

## 默认首批范围

建议首批只接入H3标准、FastH3、Veda和Qwen的服务生命周期监测，保持作业执行适配器禁用。千川、字幕清理、抖音、旧视频生成和AVCS继续观察，等各自任务提交端改走调度API后再开放。

阶段一安装器默认只监听 `127.0.0.1:18120`，Agent为 `observe` 模式，全部业务profile禁用；不会停止、重启或接管现有GPU服务。外部API、强制终止和设备权限收紧属于后续独立批准阶段。

即使管理员已经口头确认，只要预检token过期、队列状态变为未知或出现新任务，安装器也会拒绝执行并要求重新确认。

已知故障服务可以用重复的 `--exclude-service` 明确排除，但排除项会写入批准报告和approval token。排除仅表示本阶段不接管、不检查其Celery队列；不会停止、修复或改变该服务，也不能用于忽略本次要接管服务的活动任务。

## 回滚触发条件

- AID视频提交无法进入原有ComfyUI队列；
- 节点Agent把已登记服务误报为越权；
- GPU租约丢失或设备进入QUARANTINED；
- Qwen/H3无法按原方式恢复；
- 任何正在执行的生产任务受影响。

触发后立即停止新调度入口、恢复原配置和服务unit；已经运行的非抢占任务不强杀，先保留现场并通知管理员。
